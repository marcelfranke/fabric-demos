# Data dictionary

Generated by `hubdemo docs` from the row models in `src/hubdemo/models.py`.
Do not edit this file by hand: change the models and run the command again.

Every table listed here is synthetic. Passport numbers and phone numbers use
impossible patterns so no row can match a real person.

## lakehouse lh_hub

### `flights`

One arrival or departure in the bank.

Key: `flight_id`

| Column | Type | Required | Description |
| --- | --- | --- | --- |
| `flight_id` | string | yes | Key. Short id used across the kit, for example QR004. |
| `flight_no` | string | yes | Flight number as a passenger sees it, for example QR 004. |
| `direction` | one of: inbound, outbound | yes | Arriving or departing. |
| `origin` | string | yes | Airport code the flight comes from. |
| `destination` | string | yes | Airport code the flight goes to. |
| `city` | string | yes | City shown on the board for the far end of the flight. |
| `sched_time_local` | timestamp | yes | Scheduled arrival or departure, hub local time. |
| `gate_id` | string | yes | Gate, joins to gates.gate_id. |
| `other_pax_onboard` | integer | yes | Passengers on the flight who are not transferring from the inbound flight. |
| `is_synthetic` | boolean | yes | Always true. Every row in this kit is invented. |

## eventhouse eh_hub, database hubdb

### `flight_events`

One event on the stream. Written to the eventhouse, not to the lakehouse.

Key: `event_time, flight_id`

| Column | Type | Required | Description |
| --- | --- | --- | --- |
| `event_time` | timestamp | yes | When the event was raised. |
| `flight_id` | string | yes | The flight the event is about. |
| `flight_no` | string | yes | Flight number, carried so the stream reads on its own. |
| `event_type` | one of: departed, eta_update, landed | yes | What happened. |
| `eta_local` | timestamp, may be empty | no | New estimated arrival, set on eta_update. |
| `delay_min` | integer, may be empty | no | Delay in minutes, when known. |
| `source` | string | yes | Which feed raised the event. |
| `text` | string | yes | The line a person would read. |

## sql database sqldb_hub_ops

### `plans`

One proposed plan, from the rule engine or from an agent.

Key: `plan_id`

| Column | Type | Required | Description |
| --- | --- | --- | --- |
| `plan_id` | string | yes | Key. |
| `proposed_by` | string | yes | rule engine, operations agent or planner agent. |
| `created_at` | timestamp | yes | When the plan was proposed. |
| `options` | string | yes | The option chosen per onward flight, as JSON, for example {"SIN": "hold"}. |
| `outcome` | string | yes | The computed effect of the plan, as JSON. Computed in code, never by a model. |
| `status` | one of: proposed, awaiting_approval, rejected, expired, dispatched, superseded | yes | One of: proposed, awaiting_approval, rejected, expired, dispatched, superseded. |

| --- | --- | --- | --- |
